## 자동 동작

### 월요일 00:10 — 주간 등록 안내

1. 현재 날짜에 해당하는 `weekN`을 계산합니다.
2. 목표 등록 버튼이 포함된 안내 메시지를 채널에 게시합니다.
3. 새 안내 메시지를 채널의 고정됨 항목에 추가합니다.
4. 같은 봇이 게시한 이전 주간 안내 메시지를 고정 해제합니다.
5. 등록 모달에는 현재 주차만 표시합니다.

안내 메시지는 고정 해제되더라도 삭제되지 않습니다. 이전 메시지의 버튼을
누르더라도 모달은 실행 시점의 현재 주차를 사용합니다.

### 매일 00:10 — 인증 안내

- 해당 사용자의 현재 주차 미완료 목표만 조회합니다.
- 인증할 목표, 인증자료, 한 줄 회고를 입력받습니다.
- Slack List 항목을 완료 처리하고 채널에 인증 결과를 게시합니다.
- 안내 버튼은 24시간 뒤 만료시키지 않습니다.

### 매일 21:00 — 미완료 알림

현재 주차에서 완료 예정일이 오늘이거나 이미 지난 미완료 목표를 담당자별로 모아
DM으로 알립니다. 미래 날짜로 계획한 목표는 알리지 않습니다. 이전 데이터처럼
완료 예정일이 없는 목표는 매일 알림 대상에 포함합니다. 참여현황 행과 다른 주차
목표는 제외됩니다. 참여현황 집계는 알림과 함께 자동 실행되지 않습니다. 운영 기간
밖에는 DM을 보내지 않으며, 마지막 주 종료 후에도 운영자가 직접 수동 집계해야 합니다.

## 모집 정책과 구현 범위

온라인 강의, 자격증, 코딩, 독서 등 다양한 공부를 대상으로 합니다. 주간 목표량은
참여자가 정하며, 1일 1시간·주 5일은 권장 루틴입니다. 월 단위 자유 참여,
중간 참여 및 휴식을 허용합니다.

참가 보증금은 10,000원이며 주간 목표 미등록 또는 미달성 시 주당 1,000원을
차감하는 운영 정책입니다. 특별한 사유가 없으면 11월 종료 후 잔액을 정산합니다.
리워드 종류, 지급 자격, 구매 금액 및 남은 보증금의 가산 분배 기준은 아직
확정되지 않았으며 운영자가 별도로 공지합니다. 휴식 주차는 판정에서 제외합니다.

봇은 월별 신청자를 참여현황 행으로 만들고, 주간 등록·완료 수와 판정 및 누적
완료 목표 수를 집계합니다. 보증금 차감과 리워드 금액 정산은 운영자가 수동으로
처리합니다.

참가자는 `/월간등록`으로 실행 시점 주차의 월요일이 속한 달에 직접 신청합니다.
예를 들어 10/1~10/4(week3)에 실행하면 9월, 11/1(week7)에 실행하면 10월입니다. 봇이 표시한
`해당 달의 활동을 등록하시겠습니까?` 확인 모달에서 `예`를 누르면 명령을 실행한
본인의 Slack user ID로 그 달의 모든 주차 참여현황을 생성합니다. `아니오` 또는
모달 닫기는 아무것도 변경하지 않습니다. 같은 사용자의 같은 달 신청을 다시
제출해도 누락된 행만 추가하며 기존 행이나 운영자가 지정한 `휴식` 상태를
덮어쓰지 않습니다. 그 달의 모든 주차가 이미 등록된 사용자에게는 확인 모달 대신
`N월 활동에 이미 등록되어 있습니다`와 주차 목록을 보여주며 아무것도 변경하지
않습니다. Season 4 운영 기간(2026-09-14~11-29) 밖에서는 신청을 차단합니다.

## 확정된 판정 정책

- 목표 1개를 한 번 인증하면 완료되며, 여러 번 공부할 계획은 목표를 여러 개로
  등록합니다.
- 각 목표는 현재 주차의 월요일부터 일요일 사이에서 완료 예정일을 반드시 지정합니다.
- 참여자가 해당 주차에 등록한 목표를 모두 완료하면 `달성`입니다.
- 완료 목표 1개를 인증 1회로 집계합니다. 인증자료 수정은 횟수를 늘리지 않습니다.
- 인증에는 이미지 또는 PDF 파일이 필수이고 한 줄 회고는 선택입니다.
- 월별 신청 주차는 월요일이 속한 달을 따릅니다: 9월 week1~3, 10월 week4~7,
  11월 week8~11입니다.
- 월별 신청 행이 없으면 미참여로 집계에서 제외합니다. 신청 행이 `휴식`이면 해당
  주차만 판정에서 제외합니다. `참여`인데 목표가 0개면 주중에는 `등록 대기`, 주가
  끝난 뒤에는 `미등록`입니다.
- 결과 스냅샷을 별도로 고정하지 않습니다. 현재 List 상태를 다시 집계하므로 과거
  목표의 수정·삭제·완료 변경도 판정과 완료 횟수에 반영됩니다.

## 참여현황을 기존 List에 설정

운영 List는 사람이 [CSV 가져오기 템플릿](../slack-list-import.csv)으로 생성하고
소유합니다. 생성·필드 설정·검증·연결 과정은
[Slack List 생성·연결 가이드](slack-list-setup.md)를 따릅니다. 앱 직접 생성 방식은
개발·복구 용도로만 사용합니다.

| 컬럼 | 타입 | 선택값 |
|---|---|---|
| 행 구분 | 단일 선택 | 목표, 참여현황 |
| 참여 상태 | 단일 선택 | 참여, 휴식 |
| 등록 목표 수 | 숫자 | 정수 |
| 완료 목표 수 | 숫자 | 정수 |
| 판정 | 텍스트 | 봇이 계산하여 기록 |

추가한 뒤 기존 List ID를 다시 연결해 컬럼과 옵션 ID를 `.env`에 기록합니다.

```bash
python3 setup_slack_list.py --existing-list-id FXXXXXXXXXX
```

기존 목표 행은 `행 구분`이 비어 있어도 목표로 취급합니다. 새 목표에는 `목표`,
참여현황 행에는 `참여현황`을 자동 입력합니다.

## 월별 참가자 등록

일반 참가자는 Slack에서 `/월간등록`을 실행합니다. 명령에는 대상 월이나 사용자
ID를 입력하지 않으며, 실행한 사람과 현재 주차의 월요일이 속한 달을 기준으로 등록하므로 다른 사람이나
다른 달을 대신 신청할 수 없습니다.

운영자가 여러 참가자를 일괄 등록하거나 누락을 보정할 때는
`participants.example.csv`를 복사해 월별 신청자만 입력합니다.

```csv
user_id,month
U0123456789,2026-09
U0987654321,2026-10
```

```bash
cp participants.example.csv participants.csv
python3 sync_participants.py participants.csv
```

스크립트는 신청 월에 해당하는 사용자·주차 참여현황 행을 생성합니다. 같은 파일을
재실행해도 중복 행을 만들지 않으며, 운영자가 List에서 바꾼 `휴식` 상태를
덮어쓰지 않습니다. 휴식은 참여현황 행의 `참여 상태`를 직접 변경합니다.
동기화는 추가 방식입니다. CSV에서 신청자를 지워도 기존 참여현황은 삭제되지 않습니다.
월 중간 참가자도 해당 월의 모든 주차 행이 생성되므로 참가 전 주차는 운영자가
`휴식`으로 지정해야 합니다. 사용자·주차 참여현황은 한 행만 유지하세요.

현재 상태 재집계만 실행 (List의 집계 컬럼을 갱신하는 쓰기 작업):

```bash
python3 sync_participants.py --report-only
```

## 현재 구현의 제한

- 한 번에 최대 5개 목표를 등록하며 추가 등록은 가능합니다. 인증 선택창에는
  미완료 목표를 최대 100개 표시하며 완료 후 다시 열면 다음 목표가 표시됩니다.
- 스케줄러는 서버가 꺼져 있던 동안 놓친 게시를 시작 시 자동 보충하지 않습니다.
  필요하면 운영자가 `/등록발송`을 실행합니다.
- 핀 교체 실패는 로그만 남기며 자동 재시도하지 않습니다. 수동 재발송도 새 안내
  글을 생성합니다.
- 참여현황은 생성 시 등록·완료 목표 수가 0으로 시작하며 자동 갱신하지 않습니다.
  운영자가 `--report-only`를 명시적으로 실행할 때만 수치와 판정을 재집계합니다.
  잘못된 참여현황 상태나 중복
  사용자·주차 행이 있으면 집계를 중단하고 로그에 오류를 남깁니다.
- 참가자에게 List 편집 권한을 주므로 List에서 직접 완료 체크·담당자·주차·참여 상태를
  바꿀 수 있습니다. 봇의 인증자료 필수 및 운영자 휴식 정책은 봇 경로에 적용되며,
  직접 편집은 운영자가 변경 내역으로 확인해야 합니다.
- 동시에 제출한 요청이나 네트워크 타임아웃 이후 재시도는 중복 목표·게시를 만들 수
  있습니다. 저장 성공 여부가 불확실하면 List를 먼저 확인합니다.
- `/월간등록`은 동일 사용자·주차를 다시 조회해 누락분만 생성하므로 반복 제출에도
  중복 참여현황을 만들지 않습니다. 다만 여러 봇 인스턴스가 동시에 같은 요청을
  처리하는 분산 실행은 지원하지 않으므로 운영 프로세스는 한 인스턴스만 실행합니다.

## 필요한 Slack 권한

Bot Token Scopes:

```text
chat:write
chat:write.public
commands
channels:history
files:read
lists:read
lists:write
pins:read
pins:write
chat:write.customize
im:write
files:write
```

권한을 추가하거나 변경한 뒤에는 Slack App을 워크스페이스에 다시 설치하고,
새로 발급·갱신된 Bot Token이 `.env`에 설정되어 있는지 확인합니다.

Socket Mode용 App-Level Token에는 `connections:write`가 필요합니다.

## 환경 변수

앱 실행 필수값:

```dotenv
SLACK_BOT_TOKEN=xoxb-...
SLACK_SIGNING_SECRET=...
SLACK_APP_TOKEN=xapp-...
SLACK_CHANNEL_ID=C...
SLACK_LIST_ID=F...
```

수동 발송 명령을 사용할 때 필요한 값:

```dotenv
SLACK_ADMIN_USER_IDS=U운영자ID
```

이 값이 비어 있어도 앱과 자동 스케줄러는 실행되지만 세 수동 발송 명령은
모두 차단됩니다.

`setup_slack_list.py`가 `SLACK_LIST_COL_*` 및
`SLACK_LIST_OPT_WEEK1`~`SLACK_LIST_OPT_WEEK11` 값을 `.env`에 기록합니다.

## 운영 명령

| 명령 | 동작 |
|---|---|
| `/월간등록` | 참가자가 본인의 현재 주차 월요일 기준 달 참여현황 생성을 확인 후 신청 |
| `/등록발송` | 현재 주차 등록 안내를 즉시 게시하고 핀 교체 |
| `/인증발송` | 인증 안내를 즉시 게시 |
| `/알림발송` | 미완료 담당자 DM을 즉시 발송 |

운영 테스트는 `/등록발송`으로 새 메시지 게시, 새 핀 생성, 이전 핀 해제를 함께
확인합니다.

`/월간등록`은 참가자가 본인 신청에 사용하며 운영자 설정이 필요하지 않습니다.
나머지 세 명령은 `SLACK_ADMIN_USER_IDS`에 쉼표로 지정한 사용자만 `SLACK_CHANNEL_ID`의
채널에서 실행할 수 있습니다. 운영자 목록이 비어 있으면 수동 발송은 차단됩니다.
